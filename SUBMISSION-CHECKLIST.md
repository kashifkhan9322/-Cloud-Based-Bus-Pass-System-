# Submission Checklist

Use this checklist before submitting the project to a teacher, evaluator, or recruiter.

## Files and execution
- [ ] Extract the ZIP into a normal folder.
- [ ] Install Node.js 20 or later.
- [ ] Run `npm test` and keep the real test output available.
- [ ] Run `npm start` and open `http://localhost:3000`.
- [ ] Test a booking and retrieve it by ticket code.
- [ ] Capture screenshots of the home page, booking summary, confirmed ticket, and test results if required by the assignment.
- [ ] Replace the example author/student details in your cover page if your institution requires them.

## Report
- [ ] Review `README.md`.
- [ ] Review `ARCHITECTURE.md` and be prepared to explain why JSON storage must be replaced before horizontal scaling.
- [ ] Review `DEPLOYMENT.md`.
- [ ] Add actual test date, Node version, and test results to `TEST-REPORT.md`.
- [ ] Do not claim the app has been deployed to AWS unless you actually deploy it.
- [ ] Do not claim load tests or payment processing were completed when they were not.

## Demo data and security
- [ ] Use synthetic passenger details only.
- [ ] Never add real passwords, cloud access keys, payment details, or personal records to the ZIP.
- [ ] The app is an academic demo; do not use it to sell real tickets without production changes.
